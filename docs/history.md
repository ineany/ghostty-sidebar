# 변경 이력

2026-11-15에 1단계부터 14단계까지 진행했고, 2026-11-18에 15단계와 16단계를, 2026-11-23에 17단계를 진행했다.
작업을 단계별로 기록한다.
각 단계는 요청, 변경 내용, 검증, 발견한 문제 순서로 적는다.

## 커밋

공개 저장소에 올리면서 작업 중의 커밋 기록을 첫 커밋 하나로 합쳤다.
그래서 이 문서는 커밋 해시 대신 단계 번호로 변경 내용을 기록한다.

## 배경

사용자는 cmux를 쓰다가 가벼움 때문에 Ghostty로 옮겼다. Ghostty는 탭을 세로로 볼 수 없다.
Ghostty Dock, cmux, Termdock을 비교했고, Ghostty Dock의 세션 자동 저장과 비용 표시가 좋다는 평가를 받았다.
그러나 Ghostty Dock은 라이선스가 없고 설치할 때 권한을 넓게 요구한다.
그래서 기본 Ghostty를 그대로 두고 옆에 붙는 사이드바를 직접 만들기로 했다.

## 1단계: 최소 시제품

**요청:** `~/Project/github` 아래에 프로젝트를 만든다. 먼저 계획하고, 서브 에이전트에게 나눠 맡긴 뒤, 병합하고 검증한다.

**진행 방식**

1. 메인이 골격과 공유 계약(`Models.swift`)을 만들었다. `GhosttyControlling` 프로토콜, `GhosttyTab`, `GhosttyWindow`, `SessionStatus`를 정의했다.
2. 연결부 에이전트가 `feat/bridge` 브랜치에서 AppleScript 연결부, 제목 해석기, 스냅숏 해석기, 확인용 CLI(`ghostty-probe`)를 만들었다.
3. UI 에이전트가 `feat/ui` 브랜치에서 떠 있는 패널, 폴링 상태 저장소, 가짜 연결부(`--mock`)를 만들었다.
4. 메인이 두 브랜치를 병합하고 실제 Ghostty로 검증했다.

**변경 내용**

- 탭 제목 맨 앞의 기호로 Claude Code 상태를 판정한다. `✳`는 대기를 뜻한다. `◐◓◑◒`, 점자 회전 기호(U+2800~28FF), `✢✶✻✽`와 가운데 점 기호는 작업 중을 뜻한다. 전체 목록은 `TitleParser.swift`에 있다.
- 1초마다 모든 창과 탭을 읽고, 탭을 누르면 그 탭으로 전환한다.

**검증과 발견한 문제**

- Apple event 하나에 약 10ms가 걸렸다. 탭마다 속성을 읽으면 느려서, `every tab of every window` 일괄 조회로 바꿨다. 스냅숏 한 번이 약 50ms가 됐다.
- AppleScript의 `repeat with x in (id of every window)`는 Ghostty가 해석하지 못한다. id 목록을 변수에 먼저 담아야 한다.

## 2단계: 모니터 이동과 창 정렬

**요청:** 사이드바를 보조 모니터로 옮기고 싶다. 사이드바가 Ghostty를 가리지 않게 Ghostty를 옆으로 정렬하고 싶다.

**변경 내용**

- 사이드바를 고른 모니터의 왼쪽에 붙인다. 모니터 이름을 저장하고, 모니터를 뽑으면 주 모니터로 돌아간다.
- System Events로 Ghostty 창의 위치를 읽고, 사이드바와 겹치는 창만 오른쪽으로 민다(`ArrangePlanner`). 최소 너비는 400pt다.
- 새 Ghostty 창이 생기면 자동으로 정렬한다. 이 기능은 설정에서 끌 수 있다.

**발견한 문제**

- 창 정렬 스크립트가 `-1700` 오류를 냈다. `item 1 of (size of win)` 대신 창을 번호로 지정해 고쳤다.
- AppKit 좌표는 왼쪽 아래가 원점이고, 손쉬운 사용 API 좌표는 왼쪽 위가 원점이다. `y = 주 모니터 높이 - rect.maxY`로 변환한다.

## 3단계: 앱 번들과 다크 테마

**요청:** 실행 가능한 앱으로 만들고, 개발자가 좋아하는 다크 모드를 쓰고 싶다.

**변경 내용**

- `scripts/build-app.sh`가 릴리스 빌드로 `build/Ghostty Sidebar.app`을 만든다. `--install`을 주면 `~/Applications`에 복사하고 실행한다.
- 번들 ID는 `dev.local.ghostty-sidebar`다. Dock 아이콘이 없는 보조 앱(LSUIElement)이다.
- 사용자의 Ghostty 설정에 맞춰 Catppuccin Mocha 색과 D2Coding 글꼴을 쓴다. 배경 불투명도도 Ghostty와 같은 0.93이다.
- 앱 아이콘은 `scripts/make-icon.swift`가 그린다.

**발견한 문제**

- 작업 중 회전 표시를 SwiftUI TimelineView로 그렸더니 CPU를 약 7.5% 썼다. Core Animation 키프레임 회전으로 바꿔 0.7~1%로 줄였다. 회전은 설정에서 끌 수 있다.

## 4단계: 설정 메뉴 노출

**요청:** 사이드바를 보조 모니터로 어떻게 옮기는지 모르겠다. 상단 막대가 없다.

**변경 내용**

- 메뉴 막대 아이콘을 넣었다. 사이드바 보이기와 숨기기, 모니터 선택, 정렬 설정을 고를 수 있다.
- 사이드바 머리글에 설정 버튼을 넣었다. 오른쪽 클릭 메뉴와 같은 항목을 보여 준다.

**발견한 문제**

- 내장 모니터에서는 메뉴 막대 아이콘이 노치 뒤로 밀려 보이지 않았다. 그래서 머리글 설정 버튼을 함께 두었다.

## 5단계: 창 붙이기와 크기 조절

**요청:** 탭을 누르면 그 Ghostty 창이 사이드바 오른쪽에 자석처럼 붙으면 좋겠다. 높이도 조절하고 싶다.

**변경 내용**

- 탭을 누르면 그 창을 사이드바가 있는 모니터로 옮기고 사이드바 오른쪽에 붙인다(`SnapPlanner`, `GhosttyWindowSnapper`). 위쪽 끝과 높이는 사이드바와 같고, 너비는 남은 공간을 채운다.
- 사이드바의 오른쪽 끝과 아래쪽 끝을 끌어 크기를 바꾼다. 너비는 200pt에서 480pt 사이다. 맨 아래까지 끌면 다시 전체 높이가 된다.
- 크기를 바꾸는 동안 붙은 창이 함께 따라온다. 갱신은 50ms에 한 번으로 묶었다.

**검증**

| 단계 | 사이드바 | 붙은 Ghostty 창 |
|---|---|---|
| 탭 클릭 | 260×949 | x=260, 1252×949 |
| 아래쪽 끝을 위로 끌기 | 260×667 | 1252×667 |
| 오른쪽 끝을 끌기 | 330×667 | x=330, 1182×667 |

## 6단계: 손쉬운 사용 권한 문제

**요청:** 탭을 눌러도 창이 사이드바 옆으로 오지 않는다.

**원인:** 임시 서명(ad-hoc)은 빌드할 때마다 바뀐다. macOS는 손쉬운 사용 권한을 서명에 묶으므로, 다시 설치한 앱에는 예전 권한이 적용되지 않았다. 하단에 잘린 안내만 떠서 사용자가 알아채기 어려웠다.

**변경 내용**

- 권한이 없으면 사이드바 아래에 주황색 안내 상자와 "설정 열기" 버튼을 보여 준다. 1초마다 권한을 확인하고, 권한이 켜지면 안내 상자를 닫고 눌렀던 탭의 창을 붙인다.
- 빌드 스크립트가 키체인의 첫 번째 Apple Development 인증서로 서명한다. 서명이 고정되어 다시 빌드해도 권한이 유지된다. `SIGN_ID`로 다른 인증서를 고를 수 있다.

## 7단계: 끌어서 이동

**요청:** 사이드바를 끌어서 옮길 수 없나. 항상 왼쪽 위에 고정인가.

**변경 내용**

- 머리글을 끌면 사이드바가 움직인다. 다른 모니터로 옮기면 그 모니터를 저장한다.
- 화면 왼쪽이나 위쪽 끝에서 16pt 안으로 가져가면 그 끝에 붙는다. 화면 밖으로는 나가지 않는다(`PanelLayout`).
- 위치는 화면 왼쪽 위로부터의 거리로 저장한다.

**발견한 문제**

- 300pt를 끌었는데 285pt만 움직였다. 끌기 동작이 인식된 시점의 마우스 위치를 시작점으로 썼기 때문이다. 이미 움직인 거리만큼 시작점을 되돌려 고쳤다.

## 8단계: 자동 숨기기

**요청:** macOS Dock처럼 마우스를 올리면 보이고 아니면 숨는 자동 모드를 넣고 싶다.

**변경 내용**

- 마우스가 사이드바를 벗어나고 0.6초가 지나면 왼쪽으로 미끄러지며 숨는다. 화면 왼쪽 끝에 마우스가 닿으면 나타난다.
- 사이드바를 화면 끝에서 떼어 놓았다면 흐려지며 숨고, 원래 자리에 마우스를 올리면 나타난다.
- 크기 조절, 이동, 메뉴가 열려 있는 동안에는 숨지 않는다.
- 자동 숨기기를 켜면 붙은 창이 사이드바 자리까지 넓어지고, 사이드바는 창 위에 겹쳐 나타난다.

**검증:** 마우스 위치를 0.1초마다 확인하며 CPU 사용률은 0.6%였다.

## 9단계: 세션 목록, 비용, 새 탭

**요청:** 세션 자동 저장을 프로젝트 안으로 가져와 기능으로 만든다. 비용을 표시한다. 새 탭을 만드는 기능을 넣는다. 알려진 문제를 고친다.

**변경 내용**

| 기능 | 내용 |
|---|---|
| 세션 찾기 | `~/.claude/sessions/<PID>.json`에서 실행 중인 Claude 세션을 찾는다. |
| 탭과 연결 | 탭 제목과 대화 기록의 AI 제목을 비교한다. 같은 제목이 여럿이면 작업 폴더로 고른다. |
| 비용 | 탭마다 세션의 API 환산 비용을, 하단에 오늘의 합계를 보여 준다. 서브에이전트 비용도 더한다. |
| 목록 저장 | 열린 세션의 목록을 5초마다 확인해 바뀌면 저장한다. |
| 닫힌 세션 | 목록에 있지만 실행 중이 아닌 세션을 보여 주고, 누르면 `claude --resume`으로 다시 연다. |
| 새 탭 | 머리글의 "+"로 최근 폴더나 고른 폴더에서 새 Claude 세션이나 셸 탭을 연다. |

**알려진 문제 수정**

- 마지막으로 붙인 창 하나만 따라오던 것을, 붙인 창 모두가 따라오도록 고쳤다.
- 하단 시각을 24시간제로 고쳤다. 오후 5시가 "05"로 보였다.
- 탭이 하나뿐인 창은 "창 N" 머리글을 생략했다.
- 저장소 최상위에 README를 썼다.

**검증**

- 열린 탭 11개 가운데 Claude 탭 8개가 모두 맞는 세션과 연결됐다.
- 새 탭 기능으로 테스트 폴더에 탭을 열고 입력한 명령이 실행되는 것을 확인했다.

## 10단계: Codex 세션

**요청:** Codex 창도 세션 저장과 복원이 되게 한다.

**Claude와 다른 점**

- Codex는 실행 중인 세션을 알려 주는 파일이 없다.
- Codex는 실행 인자를 감춘다. `ps`에도 "codex"만 보인다.
- `codex resume`으로 다시 연 세션은 다음 질문 전까지 기록 파일을 고치지 않는다.

**변경 내용**

1. 터미널을 가진 `codex` 프로세스의 작업 폴더와 시작 시각을 libproc으로 읽는다.
2. 같은 폴더에서 프로세스 시작 직후에 만들어진 rollout 파일과 짝을 맞춘다. 실제 데이터에서 시각 차이는 1~3초였다.
3. 사이드바가 다시 연 세션은 사이드바가 ID를 기억해 짝을 맞춘다.
4. 다른 방법으로 다시 연 세션은 기록 파일이 바뀌면 찾는다.
5. 닫힌 세션 목록에 하늘색 `codex` 표시를 붙이고, 누르면 `codex resume <ID>`로 연다.

**발견한 문제**

- 처음 구현은 다시 연 Codex 세션을 놓쳤다. 위의 3번(사이드바가 ID를 기억하는 방식)을 넣어 고쳤다.
- macOS 경로는 한글이 분해형(NFD)으로 돌아오기도 한다. Swift 문자열 비교는 정규화를 고려하므로 그대로 비교해도 된다. 이를 테스트로 고정했다.

## 11단계: 성능 점검

**질문:** 이 기능 때문에 무거워진 것은 아닌가.

9단계를 시작하기 전 버전과 같은 조건의 릴리스 빌드를 80초씩 띄워 비교했다.

| 항목 | 기능 추가 전 | 처음 구현 | 고친 뒤 |
|---|---|---|---|
| 평소 CPU | 0.70~0.95% | 0.95~1.45% | 0.73~1.20% |
| 평소 메모리 | 58~63MB | 131MB | 71~78MB |
| 시작 직후 메모리 | 75MB | 319MB | 70~104MB |
| 시작 시 CPU 시간 | 0.3초 | 1.6초 | 1.5초 |

**고친 원인**

1. 오늘 쓴 Claude 기록 파일 9개, 128MB를 통째로 읽었다. 1MB씩 나눠 읽고, 조각마다 해석 결과를 풀어 주도록 바꿨다.
2. 오늘 비용을 구하려고 30초마다 모든 프로젝트 폴더를 훑었다. 5분에 한 번으로 줄이고, 그 사이에는 오늘 쓴 파일만 읽는다.
3. Codex 기록 파일 30일 치를 5초마다 훑었다. 프로세스가 바뀌거나 1분이 지났을 때만 다시 찾는다.

## 12단계: 역할 정리와 저장 위치 이동

**질문:** 세션 저장은 Claude와 Codex의 일이고, 사이드바는 매칭과 목록 관리가 역할이지 않나.

**결정:** 대화 저장은 Claude와 Codex가 맡는다. 사이드바는 세션을 찾고, 탭과 짝을 맞추고, 열려 있던 세션의 목록을 관리한다.

**변경 내용**

- 목록을 `~/.claude/session-restore/`와 `~/.codex/session-restore/`에서 `~/Library/Application Support/Ghostty Sidebar/sessions/`로 옮겼다.
- 처음 실행할 때 예전 위치의 목록을 한 번 옮겨 온다. 실제로 Claude 세션 9개, Codex 세션 2개가 옮겨졌다.
- 예전 `~/.local/bin/cc-session` 스크립트와 `~/.codex/session-restore/` 폴더를 휴지통으로 보냈다.

## 13단계: 닫힌 세션 접기와 직접 닫은 세션 보관

**요청:** 닫힌 세션을 따로 묶어 접어 두면 좋겠다. 의도적으로 닫은 세션도 아직 살릴 수 있으니 보이면 좋겠다.

**변경 내용**

- "닫힌 세션" 그룹은 처음에 접혀 있고 개수만 보여 준다. 펼침 상태는 기억한다.
- 펼치면 "비정상 종료"와 "최근에 닫음"으로 나뉜다. "모두 열기"는 비정상 종료 묶음에만 있다.
- 직접 닫은 세션은 `closed.json`에 최근 7일, 최대 30개까지 남긴다. 대화 기록 파일이 지워진 세션은 한 시간마다 확인해 뺀다.
- 이력 사본은 10분에 한 번만 남긴다. 목록이 자주 바뀌면 10개 제한 때문에 예전 사본이 몇 분 만에 밀려났기 때문이다.

**검증**

| 상황 | 결과 |
|---|---|
| 탭 하나를 닫음 | "최근에 닫음"에 들어감 |
| 그 줄을 클릭 | 새 탭에서 다시 열리고 목록에서 빠짐 |
| 두 탭을 한꺼번에 닫음 | "비정상 종료"에 들어가고 열린 세션 목록에 남음 |

## 14단계: 닫은 Codex 탭이 "최근에 닫음"에 나오지 않는 문제

**신고:** 방금 닫은 Codex 탭이 새로 고침을 해도 "최근에 닫음"에 나오지 않는다.

**원인**

- 같은 폴더에서 Codex가 두 개 돌고 있었다. 하나는 닫은 탭의 Codex였고, 하나는 Ghostty 밖에서 띄운 Codex였다.
- 탭을 닫자 사이드바가 닫힌 세션의 기록 파일을 다른 Codex의 것으로 다시 짝지었다. 그 기록 파일이 다른 Codex의 시작 시각 뒤에 수정됐기 때문이다.
- 세션이 계속 실행 중인 것으로 보였으므로 "최근에 닫음"에 들어가지 않았다.
- 같은 폴더에서 먼저 시작한 프로세스가 나중 프로세스의 새 기록 파일을 가로챌 수 있는 문제도 함께 찾았다.

**변경 내용**

- 프로세스가 끝나면, 그 세션을 짝짓기 전에 "끝남"으로 표시한다. 끝난 세션은 기록 파일이 다시 써지기 전까지 다른 프로세스에 붙이지 않는다.
- 한번 짝이 맞은 프로세스는 그 세션을 유지한다.
- 추정 단계에서는 `~/.codex/thread-writer-locks/<ID>.lock`이 있는 세션만 고른다. Codex가 열린 세션마다 두고 종료할 때 지우는 파일이라, 사이드바를 다시 시작해도 판단할 수 있다.
- 새 기록 파일은 같은 폴더에서 그 파일이 만들어지기 직전에 시작한 프로세스에 붙인다.
- "최근에 닫음"에 있는 Codex 세션의 닫은 시각도 같은 판단에 쓴다.

**검증:** 실제 데이터에서 실행 중인 Codex 세션이 하나로 맞게 나왔다. 단위 테스트 4개를 더해 66개가 모두 통과했다.

## 15단계: DMG 배포본

**요청:** 배포본을 DMG로 만들 수 있는지 물었다.

**변경 내용**

- `scripts/make-dmg.sh`를 추가했다. 앱을 빌드하고 `build/Ghostty-Sidebar-<버전>.dmg`를 만든다.
- DMG에는 앱과 Applications 폴더 바로가기가 들어 있다. 앱을 바로가기로 끌어 놓으면 설치된다.
- `build-app.sh`에 `UNIVERSAL=1` 옵션을 넣었다. 이 옵션을 켜면 Apple Silicon과 Intel에서 모두 도는 실행 파일을 만든다. DMG 스크립트는 항상 이 옵션을 켠다.
- 두 아키텍처로 빌드하려면 Xcode가 필요하다. DMG 스크립트는 시작할 때 Xcode가 선택되어 있는지 확인한다.

**검증:** DMG를 마운트해 앱, 바로가기, 두 아키텍처, 체크섬을 확인했다. 크기는 2.3MB다.

**한계:** Apple Development 인증서로 서명했으므로 `spctl`이 앱을 거부한다. 다른 Mac에서는 Gatekeeper가 첫 실행을 막는다. 경고 없이 배포하려면 Developer ID Application 인증서로 서명하고 공증을 받아야 한다.

## 16단계: 프로젝트별 보기

**요청:** Orca의 사이드바는 프로젝트별로 묶는다. 비교해서 차용할 점을 제안하고, 그중 네 가지를 구현해 달라고 했다.

**변경 내용**

- 설정에 "프로젝트별로 묶기"를 추가했다. 기본값은 꺼짐이고, 켜지 않으면 지금처럼 창별로 보여 준다.
- 탭의 작업 폴더에서 위로 올라가며 `.git`이 있는 폴더를 찾고, 그 폴더를 프로젝트로 본다. git 저장소가 아니면 작업 폴더 자체가 프로젝트다. 작업 폴더를 모르는 탭은 "기타"에 넣는다.
- 프로젝트 머리글에 대기 수, 작업 중 수, 비용 합계, 탭 수를 보여 준다.
- 머리글의 "+"를 누르면 그 프로젝트 폴더에서 새 Claude 세션을 연다. 오른쪽 클릭 메뉴에는 새 셸 탭과 Finder에서 열기가 있다.
- 닫힌 세션은 두 묶음을 합쳐 프로젝트별로 묶고, 최근에 쓴 세션을 위에 둔다. 비정상 종료한 세션에는 "비정상" 표지를 붙인다.
- 차용하지 않은 점: Orca처럼 worktree를 만들고 관리하는 기능은 사이드바의 역할 밖이라 넣지 않았다.

**코드 리뷰에서 찾아 고친 문제**

- Ghostty는 창을 앞에서 뒤 순서로 알려 준다. 그래서 다른 창을 앞으로 가져올 때마다 프로젝트 순서가 바뀌었다. 창이 처음 나타난 순서를 기억해 쓰도록 고쳤다.
- 폴더 확인은 메인 스레드에서 한다. 잠든 외장 디스크나 네트워크 드라이브가 있으면 화면이 멈출 수 있어서, 홈 폴더 아래의 경로만 확인하도록 고쳤다. 캐시는 항목마다 60초 뒤에 만료한다.
- 닫은 시각과 마지막 활동 시각을 서로 다른 형식의 문자열로 비교하고 있었다. 날짜 값으로 비교하도록 고쳤다.
- 머리글 아무 곳에나 마우스를 올려도 "+"가 강조되던 문제를 고쳤다.

**검증:** 단위 테스트 10개를 더해 76개가 모두 통과했다. 가짜 데이터 모드에서 화면을 캡처해 묶인 결과를 확인했고, 잘리던 프로젝트 이름을 고쳤다.

## 17단계: 직접 닫은 Codex 세션이 비정상 종료로 나오는 문제

**신고:** 닫은 Codex 창이 모두 "비정상" 표지를 달고 나온다. 비정상 종료의 기준이 한 번에 두 개 이상 닫히는 것인지 물었다.

**원인**

- `codex.json`은 2026-11-16 22:39 뒤로 바뀌지 않았다. 그 안에 이미 닫은 Codex 세션 두 개가 남아 있었다.
- 실행 중인 세션이 0개이면 목록을 쓰지 않는 규칙을 Claude와 Codex에 따로 적용했다. 마지막 Codex를 닫으면 Codex 실행 수가 0이 되므로 목록이 그대로 남았다.
- 사이드바를 다시 설치해 시작하자, 목록에 남은 세션이 비정상 종료로 분류됐다. 시작할 때 비정상 종료가 "최근에 닫음"보다 우선했으므로 `closed.json`의 Codex 기록도 버려졌다.

**변경 내용**

- 그 종류의 세션이 0개가 되어도 열린 세션 목록을 다시 쓴다. Ghostty 종료로 한꺼번에 끝난 세션은 "비정상 종료"에 있으므로 목록에 남는다.
- 시작할 때 두 목록에 모두 있는 세션은 "최근에 닫음"으로 본다.

**검증:** 빌드와 단위 테스트 76개가 통과했다. 이미 남아 있던 두 세션은 닫은 시각 기록이 없어 자동으로 고칠 수 없다. 사용자가 ×로 한 번 지워야 한다.
